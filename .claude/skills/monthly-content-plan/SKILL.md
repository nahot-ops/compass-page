# 月間企画の提案

毎朝のレポートと、伸びた投稿を全部読み込み、
「今月はこの企画」を1本に絞って提案するスキル。

候補を並べて終わりにしない。
最後は必ず「主企画1本＋週ごとの投稿案」まで落とす。

## 参照ファイル

このスキルのもの:

- references/buzz-factors.md ……過去に伸びた投稿の共通点（バズ因子リスト）
- references/hook-criteria.md ……損失回避／利得／意外性の判定基準
- references/monthly-template.md ……月間企画の出力形式
- references/area.md ……久米エリアの考え方（地元アンカー・地元回・学校名ルール）

毎朝のレポート用スキル（viral-finder-report）と共有するもの:

- ../viral-finder-report/references/genres.md ……20ジャンルとNG
- ../viral-finder-report/references/viral-criteria.md ……ランク基準

ジャンル番号とランク（S／A／B／参考）は、毎朝のレポートと同じものを使う。
定義を二重に持たない。

## 手順

### 1. 材料を全部集める

データはGoogleドライブの「伸び投稿レポート」フォルダにある。

- 親フォルダ「伸び投稿レポート」: `1Zp7rxgXd1_3l4XPtD9K5Aj_abALDbcIZ`
- 「01_気になった競合投稿」: `1L6YXgGZvNoRdcBBt3dzU7nhjSCdIwtFy`
- 「02_毎朝のレポート」: `1EqNciBCBlvWNMHJgZKPkAPX4u47vjDkI`
- 「03_月間企画」: 親フォルダの中にある（無ければ手順7で作る）

読む順番:

1. 「02_毎朝のレポート」のレポートを全部読む
   - `search_files` で `parentId = '1EqNciBCBlvWNMHJgZKPkAPX4u47vjDkI'` を検索
   - 次ページトークンが無くなるまで追い、`read_file_content` で全件読む
   - 「全部」が原則。直近だけに絞らない
2. 「01_気になった競合投稿」の中身を確認する
   - レポートに載っていない投稿と、Nahoのメモ（Googleドキュメント）を拾う
   - 画像は、レポートで分析済みなら読み直さなくてよい
3. 「03_月間企画」の過去の企画書を読む
   - 先月の主企画と、その結果メモ（あれば）を拾う
   - 同じ企画の繰り返しを避けるため
4. 自分の投稿の数字があれば使う
   - Nahoが会話に貼ったインサイトのスクショ・CSV・メモ
   - 無ければ聞くだけ聞いて、無いまま進めてよい
5. 問い合わせの流入元を確認する
   - Notionの問い合わせ記録（「問い合わせ・体験管理」など）を `notion-search` で探す
   - 久米エリアからの問い合わせが、どこ経由で来ているかを拾う
   - 記録が無ければ「未記録」とする

レポートが1本も無いときは、企画を作らず
「伸び投稿レポートがまだありません」と1行で報告して止まる。
データを推測で作らない。

### 2. 伸びた投稿を一覧にする

全レポートから、投稿ごとに次の項目を1行にまとめる。

- 日付 / アカウント / 形式 / テーマ一言
- ランクと伸び方の型（保存型・シェア型・DM型・拡散型）
- 適合ジャンルと適合度
- レポートの「なぜ伸びたか」の要点
- Nahoのメモ（あれば）

同じ投稿が複数のレポートに出ていたら、1件にまとめる。
「推定」と書かれたランクは、推定のまま扱う。

### 3. バズ因子を当てはめて、リストを更新する

一覧の各投稿に、references/buzz-factors.md の因子を当てはめる。
1投稿につき、効いている因子を1〜3個選ぶ。

そのあと、因子ごとに「当てはまった投稿数」を数え直す。
数え直した結果で、確度（仮説／傾向／定番）を付け直す。

どの因子にも当たらない共通点が2件以上で見つかったら、
新しい因子として「仮説」で追加候補にする。

リストの書き換えは、企画書の中で「更新案」として見せる。
buzz-factors.md そのものは、Nahoの了承を取ってから直す。

### 4. 今月の種を拾う

今月の時期と照らして、企画の種を3〜5個拾う。

- レポートの「使える切り口」のうち、まだ投稿していないもの
- 今月〜来月の学校行事・季節イベント（buzz-factors.md の時期カレンダー）
- 今月の募集状況（Notion「集客・定着プロジェクト」。分かる範囲で）
- 久米エリアの学校行事・愛媛の高校入試の動き（Nahoが確認済みのものだけ）

競合の投稿から借りるのは型まで。
題材は、久米エリアの保護者が自分ごとにできるものを選ぶ（references/area.md）。

種ごとに「事実」と「解釈」を分けて書く。
事実はどのレポートの何から来たかを添える。

### 5. 企画候補を3つ作り、採点する

種とバズ因子を掛け合わせて、企画候補を3つ作る。
3つは主軸のフックが重ならないようにする。

採点は references/hook-criteria.md の採点表で行う。順番は次のとおり。

1. NGチェック（1つでも当たれば除外）
2. フック3軸（損失回避／利得／意外性）の点数
3. バズ因子の該当数と確度
4. 集客適合（今月の募集や講座の動きに合っているか）
5. エリア適合（久米エリアの保護者が自分ごとにできるか）

「伸びやすい」と「来てほしい家庭に届く」は別物。
同点なら、エリア適合 → 集客適合の順で高い方を取る。

### 6. 主企画を1本に決め、テンプレートに落とす

最高点の候補を主企画にする。
選ばなかった2案は、理由を1行ずつ残す（翌月以降の種になる）。

references/monthly-template.md の形式で書く。
投稿の割り振りは、今の運用枠に合わせる。

- 月曜：中学生保護者向け（ComPass）
- 木曜：小5・小6とComPassキッズ向け（ComPass）
- 方眼ノート講座（ジャンル14〜20）の企画は、別枠として分けて書く

ComPass枠は、references/area.md に沿って組む。

- 全投稿に、地元アンカーを1つ以上入れる
- 2週に1本（月2本）を「地元回」にして、学校名や地域の行事を出す
- 地元回は、学校名ルールを満たしているかを投稿ごとに確認する

画像作成と実投稿は、Nahoが手動で行う。
このスキルは企画とフック・構成の骨子までを担当する。

### 7. Googleドキュメントで出す

保存先は「伸び投稿レポート/03_月間企画」。

- フォルダが無ければ、`create_file` で親フォルダ内に
  `03_月間企画`（mimeType `application/vnd.google-apps.folder`）を作る
- 作れなければ、親フォルダに直接置き、その旨を報告する

ドキュメントは `create_file` で作る。

- title: `月間企画 YYYY年M月`
- contentMimeType: `text/markdown`
- textContent: 企画書本文（Markdown）

同じタイトルがあれば上書きせず、末尾に「（2）」を付ける。
既存ファイルを削除・ゴミ箱移動しない。

作成後に `read_file_content` で読み返し、
見出しと本文が入っているか確認してから報告する。

Markdown変換の注意:
- 単独の改行は前の行とつながる。分けたいときは空行か箇条書きにする
- 太字（**）は使わない

チャットには、主企画の1行と週ごとの投稿タイトル、
ドキュメントのリンクだけを返す。

## 守ること

ComPassのブランドで、次は使わない。

- 「点数保証」、点数・偏差値の実数、合格実績の数字
- 「管理型」「詰め込み型」
- 「チームで学ぶ塾」
- 生徒が特定できる情報（氏名・学校名・筆跡が分かるノート写真）
- 学校の評価、確認していない学校行事の日程（references/area.md の学校名ルール）

競合の文言はそのまま写さない。
構造と感情だけ借りて、言葉は自分の現場に置き換える。

損失回避は「不安をあおる」とは違う。
詳しくは hook-criteria.md の「やりすぎライン」を見る。

## 文体ルール（企画書本文）

- 一人称は「僕」、です・ます調ベース
- 1文60文字以内。改行を多めに、スマホで読みやすく
- 太字（**）は使わない。強調は【】か見出しで
- 専門用語には（）で補足を付ける
- 「いかがでしたか」などの定型句は禁止
