# バイラルファインダー 朝の伸び投稿レポート

競合アカウントの伸び投稿から、
自分の発信に転用できるネタだけを毎朝拾うスキル。

判定に使う定義は references/ にまとめてある。
基準を変えたいときは、そのファイルだけ直せばいい。

- references/genres.md ……自分の20ジャンルと判定軸
- references/viral-criteria.md ……「伸び投稿」の数値基準
- references/report-template.md ……レポートの出力形式

## 手順

### 1. 今日のデータを集める

データはGoogleドライブに置かれる。

- 親フォルダ「伸び投稿レポート」: `1Zp7rxgXd1_3l4XPtD9K5Aj_abALDbcIZ`
- データ置き場「01_バイラルファインダーのデータ」: `1L6YXgGZvNoRdcBBt3dzU7nhjSCdIwtFy`
- レポート置き場「02_毎朝のレポート」: `1EqNciBCBlvWNMHJgZKPkAPX4u47vjDkI`

Google Drive コネクタの `search_files` で
`parentId = '1L6YXgGZvNoRdcBBt3dzU7nhjSCdIwtFy'` を検索し、
次の順で使うファイルを決める（次ページトークンが無くなるまで追う）。

1. タイトルに今日の日付（YYYY-MM-DD / YYYYMMDD / M月D日）が入ったファイル
2. 無ければ、作成日時（createdTime）が今日のファイル全部
3. それも無ければ、いちばん新しいファイル（7日以内のものに限る）

中身の読み方:
- スプレッドシート・Excel・PDF・画像 → `read_file_content`
- CSV → `download_file_content` で取得してデコード
- 画像（スクショ）は写っている数字だけを使い、読めない数字は欠損扱い

対象が無い、または7日以上前のものしか無ければ、
レポートを作らず「今朝のバイラルファインダーのデータが置かれていません」
と1行で報告して止まる。データを推測で作らない。
会話中にユーザーがデータを直接貼った場合は、それを使ってよい。

ファイルが今日の日付でなければ、レポート冒頭に
「◯月◯日のデータで作成」と明記する。

取り込む項目（列名の揺れは意味で対応づける）:
アカウント名 / フォロワー数 / 投稿URL / 投稿日 / 投稿形式 /
本文・キャプション / 再生数 / いいね / コメント / 保存 / シェア / DM送信 /
アカウント平均（あれば）

### 2. 「伸び投稿」を選別する

references/viral-criteria.md の基準で、各投稿に
S / A / B / 対象外 のランクを付ける。
対象外は以降の処理から外す。

保存・シェア・DMの数値がデータに無い投稿は、
同ファイルの「数値が欠けているとき」のルールに従う。

### 3. ジャンル適合を判定する

伸び投稿ごとに references/genres.md の20ジャンルと照らし、
適合度を 0〜3 で付ける。

- 3 ……テーマも読者もそのまま重なる
- 2 ……読者は重なる。切り口を変えれば使える
- 1 ……構成・フックだけ借りられる
- 0 ……使えない

各ジャンルの「NG」に当たる場合は、他が合っていても 0 にする。
適合度 2 以上の投稿だけをレポート本編に載せる。
適合度 1 は「型だけ借りる枠」として末尾にまとめる。

### 4. なぜ伸びたかを分析する

数字とキャプション（あれば画像・動画の内容）から、
次の観点で「伸びた理由」を2〜3行で言語化する。

- フック（1枚目・冒頭1秒・1行目で何を言ったか）
- 保存理由（後で見返す価値は何か）
- シェア・DM理由（誰に送りたくなるか）
- 感情（共感・驚き・不安解消・あるある）
- 形式（リール / カルーセル / 一枚画像、尺・枚数）

「なんとなく良い」は書かない。
数字のどれが突出しているかと必ずセットで書く。

### 5. 使える切り口を3つ出す

適合ジャンルごとに、そのまま投稿案にできる切り口を3つ作る。
3つはそれぞれ違う角度にする（例: 塾視点 / 保護者視点 / 方眼ノート視点）。
各切り口に「1行目のフック案」を付ける。

競合の文言をそのまま写さない。
構造と感情だけ借りて、言葉は自分の体験・現場に置き換える。

### 6. レポートを出す

references/report-template.md の形式で書く。

保存先はGoogleドキュメント。
Google Drive コネクタの `create_file` で次のように作る。

- title: `伸び投稿レポート YYYY-MM-DD`
- parentId: `1EqNciBCBlvWNMHJgZKPkAPX4u47vjDkI`
- contentMimeType: `text/markdown`
- textContent: レポート本文（Markdown）

Markdownは自動でGoogleドキュメントに変換される。
変換時の注意:
- 単独の改行は前の行とつながる。行を分けたいときは
  空行を入れるか、箇条書き（`- `）にする
- 太字（**）は使わない

作成前に、同じフォルダに同じタイトルが無いか検索する。
あれば上書きせず、タイトル末尾に「（2）」を付ける。
既存ファイルを削除・ゴミ箱移動しない。

作成後に `read_file_content` で読み返し、
見出しと本文が入っているか確認してから報告する。

- チャットには「今日のトップ3」と、ドキュメントのリンクを返す
- 載せる上限は10投稿。多い日はランク→適合度の順で絞る
- 伸び投稿が0件の日も「該当なし」と、基準に一番近かった1件を出す

## 文体ルール（レポート本文）

- 一人称は「僕」、です・ます調ベース
- 1文60文字以内。改行を多めに、スマホで読みやすく
- 太字（**）は使わない。強調は【】か見出しで
- 専門用語には（）で補足を付ける
- 「いかがでしたか」などの定型句は禁止

## 定期実行について

毎朝の自動実行は、このスキルを呼ぶ定期タスクとして設定する。
例: 平日 7:00 に「/viral-finder-report を実行して」を送る。
バイラルファインダーの書き出しをドライブの「01_バイラルファインダーのデータ」に
置く運用が前提。置かれていなければ手順1の通り止まって依頼する。
